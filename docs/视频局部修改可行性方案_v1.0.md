# 已生成视频的「局部修改」可行性方案 v1.0

> 状态：可行性调研 · 日期：2026-10-13
> 范围：对**已经生成好的视频**（本地 mp4）做 AI 局部修改，接入到 conatus_viva 现有管线。
> 本文只做可行性与实施路线评估，**不是设计 spec**，不含最终接口冻结。

## 1. 背景与目标

现有管线（`lib/pipeline/`，纯 Dart）已经能通过阿里百炼 DashScope 生成视频：
- 相册模式：`wan2.6-i2v-flash` 图生视频；
- 文生视频模式：`wan3.0-video`（`text_to_video.dart`）；
- 主讲人工具：文生视频 + ffmpeg 叠加头像（`speaker_video.dart`）。

需求：**拿一条已经生成的视频，只改其中一部分**，不改整体。用户确认要三类能力：
1. **指令式局部替换**（用 prompt + 可选参考图描述改什么）；
2. **画 mask 精确区域编辑**（指定区域增/删/改）；
3. **视频换人**（用一张人物图替换视频里的人）。

## 2. 结论速览

- 阿里百炼已有现成的「视频编辑」异步接口，**端点与协议和现有 `wan3.0` 文生视频完全一致**：`POST /api/v1/services/aigc/video-generation/video-synthesis`（`X-DashScope-Async: enable`）提交，`GET /api/v1/tasks/{task_id}` 轮询，`output.video_url` 下载（24h 有效）。
- 现有 `DashScopeVideoClient`（`dashscope_video.dart`）的 `postTask / poll / downloadClip / parseVideoTask` 可**直接复用**，新工作只是「换 request body」+「把本地 mp4 变成模型可读的 URL」。
- **最大卡点**：视频输入必须是**公网 URL 或 `oss://` 临时 URL**，**不支持 base64**（只有参考图支持 base64）。现有 `uploader.dart` 只会上传**图片**，且方法用错（见 §5.2），需要新增/修正视频上传。
- 官方提供**免费临时上传**（48h）换 `oss://` URL，足以支撑原型；生产需自备 OSS。

## 3. 可选模型能力对照

（均来自官方 API 文档，2026-10 核对）

| 模型 ID | 编辑语义 | 输入视频 | 输出时长 | 分辨率 | 音频 | 显式 mask | 文档 |
|---|---|---|---|---|---|---|---|
| `happyhorse-1.0-video-edit` | 指令编辑 + 0–5 张参考图（风格转换、局部替换） | 公网 URL，3–60s，≤100MB，8–60fps | 3–15s（超 15s 自动截前 15s） | 720P/1080P | ✅ `audio_setting=origin` 可保留原声 | ❌ | HappyHorse-视频编辑 |
| `wan2.7-videoedit` | 指令编辑 + 视频迁移（特效/运镜复刻） | 公网/临时 URL，2–10s，≤100MB | ≤10s | 720P/1080P | ✅ `audio_setting` | ❌ | 万相2.7-视频编辑 |
| `wan2.1-vace-plus`（旧） | **局部编辑** `function=video_edit`；也含视频重绘/延展/画面扩展/多图参考 | MP4，≤5s，≥16fps，≤50MB | **固定 5s** | 仅 720P | ❌ 无音频 | ✅ `mask_image_url`/`mask_video_url` + `mask_frame_id` + `tracking/fixed` | 万相-视频编辑（2.1） |
| `wan2.2-animate-mix` | 视频换人（用图片替换视频里的人） | video + image，2–30s | 2–30s | 仅 720P | — | ❌（按人） | 万相-视频换人 |

选型建议：
- **指令式局部替换** → `happyhorse-1.0-video-edit`（文档首推、有声、15s、body 最接近现有代码）。
- **mask 精确区域** → `wan2.1-vace-plus`（唯一支持显式 mask），代价：5s 上限、720P、**无声音**（对依赖方言口播的场景要另配音/拼接）。
- **换人** → `wan2.2-animate-mix`（人物级替换，非 mask）。

## 4. 端到端实现链路

```
本地 mp4 ──①上传换 oss:// URL──► DashScope 临时存储
                                    │
                  ② submit(编辑请求，带 X-DashScope-OssResourceResolve: enable)
                                    ▼
              POST .../video-generation/video-synthesis  →  task_id
                                    │
                  ③ 轮询 GET /api/v1/tasks/{task_id}（15s 间隔）
                                    ▼
              SUCCEEDED → output.video_url（24h）
                                    │
                  ④ 立即下载转存本地 ►  结果 mp4
```

### 4.1 上传（关键，官方两步流）

1. `GET {host}/api/v1/uploads?action=getPolicy&model={编辑模型}`（`Authorization: Bearer <key>`）→ 返回 `data.{policy, signature, upload_dir, upload_host, oss_access_key_id, x_oss_object_acl, x_oss_forbid_overwrite, expire_in_seconds, max_file_size_mb}`
2. `POST {data.upload_host}`，`multipart/form-data` 字段：`OSSAccessKeyId`、`Signature`、`policy`、`x-oss-object-acl`、`x-oss-forbid-overwrite`、`key={upload_dir}/{文件名}`、`success_action_status=200`、`file`（**file 必须最后**）
3. URL = `oss://{key}`，有效期 **48h**

约束：上传的 `model` 必须与后续调用模型**一致**；与 API Key **同主账号**；上传凭证限流 100 QPS；**官方明确"请勿用于生产"**。

### 4.2 提交（以 `happyhorse-1.0-video-edit` 为例）

```json
{
  "model": "happyhorse-1.0-video-edit",
  "input": {
    "prompt": "把视频里女孩的衣服换成图片里的衣服",
    "media": [
      { "type": "video", "url": "oss://dashscope-instant/xxx/....mp4" },
      { "type": "reference_image", "url": "data:image/png;base64,..." }
    ]
  },
  "parameters": { "resolution": "720P", "watermark": false, "audio_setting": "origin" }
}
```
请求头在现有基础上**必须新增** `X-DashScope-OssResourceResolve: enable`（用 `oss://` 时；缺少会报 URL 解析失败）。

其它两种模式的差异：
- `wan2.1-vace-plus` 局部编辑：`input.function="video_edit"`、`input.video_url`、`input.mask_image_url`（+`mask_frame_id`）/`mask_video_url`，`parameters.mask_type/expand_ratio/expand_mode/control_condition`。
- `wan2.2-animate-mix`：video + 人物图，另有主体/背景模式参数（pro/std）。

### 4.3 计费

- `happyhorse` / `wan2.7`：`output.usage.duration = input_video_duration + output_video_duration`（约视频长度的 2 倍×秒单价）。
- `wan2.1-vace-plus`：`output.usage.video_duration`。
- **单价已核实（华北2 北京，2026-10）**：`wan2.7-videoedit` 720P **0.6 元/秒**、1080P **1 元/秒**（输入+输出双计，免费额度 50 秒）；`happyhorse-1.0-video-edit` 720P 0.9、1080P 1.6 元/秒；`wan2.1-vace-plus` 720P 0.70 元/秒。一条 N 秒素材（输出等长）≈ `2N × 单价`。完整单价与口径见 [万相视频生成与编辑成本核算 v1.0](万相视频生成与编辑成本核算_v1.0.md)。

## 5. 与本仓库的衔接

### 5.1 可直接复用
- `dashscope_video.dart`：`DashScopeVideoClient` 的 submit/poll/download + `parseVideoTask` + 错误分类（408/429/5xx→transient，其余→fatal）。
- `text_to_video.dart`：submit→poll→download 的驱动器骨架（可复制为 `editVideo`）。
- `ffmpeg.dart`：`mediaDurationSeconds` 测时长、`concatArgs/writeConcatList` 拼接（用于超时长分片）。
- `config.dart` / `pipeline_config.example.json`：加 `video_edit` 配置段。
- `api_router.dart` / `pipeline_server.dart`：新增路由照抄现有 t2v 三条。

## 6. 分阶段路线

**Phase 1 — 库 + CLI 冒烟（打通托管链路，最高优先）**
- 产出：`file_uploader.dart` + `video_edit.dart`(client/driver) + CLI 模式 + 配置段。
- 目标：本地 mp4 → 上传换 URL → 调 `happyhorse-1.0-video-edit` → 下载结果，端到端跑通一条真·付费调用。
- 不做 Web、不做 mask 画板。

**Phase 2 — Web「指令式」模式**
- Server：`POST /api/edit`、`GET /api/edit/:id`、`GET /api/edit/:id/video`（可注入 `VideoEditRunner` 测试 seam）。
- 前端：新增「视频编辑」模式——上传 mp4 + 指令 +（可选）参考图（参考图可 base64 免上传）+ 费用确认 → 轮询 → 预览/下载。

**Phase 3 — mask 精确区域 + 换人（后置）**
- mask：前端加首帧画板产出 `mask_image`，接 `wan2.1-vace-plus`；注意 5s/720P/无声。
- 换人：接 `wan2.2-animate-mix` + 人物图上传。

## 7. 关键约束汇总

| 维度 | 约束 |
|---|---|
| 视频输入格式 | `happyhorse`/`wan2.7` 支持 MP4、MOV；VACE 仅 MP4 且 ≥16fps |
| 输入时长 | happyhorse 3–60s；wan2.7 2–10s；VACE ≤5s |
| 输出时长 | happyhorse ≤15s；wan2.7 ≤10s；VACE 固定 5s |
| 大小 | ≤100MB（VACE ≤50MB） |
| 分辨率 | happyhorse/wan2.7 720P/1080P；VACE/换人 仅 720P |
| 音频 | happyhorse/wan2.7 可保留原声；VACE **无声** |
| 输入 URL | 视频只能公网/`oss://`，**不能 base64**；参考图可 base64 |
| 结果 URL | 24h 有效，需立即下载 |
| 托管 | 临时上传 48h、模型绑定、100 QPS、不建议生产 |
| 计费 | （输入+输出）时长×秒单价；wan2.7-videoedit 720P ¥0.6/秒、1080P ¥1/秒 |

## 8. 风险与冒烟验证清单（Phase 1 要逐条验证）

1. workspace 主机（`https://{id}.cn-beijing.maas.aliyuncs.com`）是否支持 `GET /api/v1/uploads?action=getPolicy`；不支持则 policy 走默认 `https://dashscope.aliyuncs.com`。
2. Dart（`package:http`）向 `upload_host` 发 multipart 上传是否成功、返回 `oss://`。
3. 提交时带 `X-DashScope-OssResourceResolve: enable` 后，`oss://` 能否被 `video-synthesis` 接受。
4. 上传所用 model 与调用模型一致（否则失败）。
5. 超过模型时长上限的视频如何处理：先"明确报错"（Phase 1），或分片→逐段编辑→拼接（后续；分片编辑可能有一致性/接缝问题）。
6. 成本：单价已按官方定价填实（见 §4.3），跑通后按实际账单校准。
